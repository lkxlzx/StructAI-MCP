# StructAI MCP 能力扩展 —— 执行任务列表 v1.0

> 排序原则：**先零成本窗口 → 再情报 → 再架构 → 再功能 → 最后收敛**。
> 每一步都有可客观验收的产物，不依赖未定决策。

---

## 排序的三条依据

**① 零成本窗口正在关闭。**
`tool_interfaces` 与 `capabilities` 两张表**当前都是 0 行**（能力表是代码里的手写字典）。
现在改 schema 成本为零；灌入约 1,400 行之后再改，就要写迁移。**所以 schema 必须排第一。**

**② 先要情报，再谈架构。**
"手册里到底能抽出多少可用接口定义"**当前无人知道**。抽取管线做完才有这个数字，
而它直接决定后面各阶段的实际规模。**不要凭猜测设计架构。**

**③ 最高风险项排在情报之后、功能之前。**
阶段 3（能力表入库）触及核心调用路径，现有 387 个测试全部依赖手写表。
它必须**单独占一个阶段**，并配双轨过渡与单条验证，不与功能改动混在一起。

# 阶段 2 · 风险前置：单条能力双轨验证

> **为什么单独成阶段**：阶段 3 是**唯一的高风险项**（触及核心调用路径，387 个测试全依赖手写表）。
> 先用**一条**能力证明"数据库驱动的行为与手写完全一致"，再动整张表。

| ID | 任务 | 验收 |
|---|---|---|
| **2.1** | 把 `node.list` **一条**能力同时写进数据库与手写表 | 两处数据可对比 |
| **2.2** | 加一个开关：`capability_table()` 可从库读**这一条** | 开关关闭时行为与今天**逐字节一致** |
| **2.3** | 对同一条能力跑现有全部相关测试 | **387 个测试全过**，两种来源结果相同 |
| **2.4** | 记录差异（若有）：缓存、启动顺序、异常路径 | 差异清单（预期为空） |

**为什么值得单独做**：如果直接迁移 162 条后发现行为有偏差，**排查面是整张表**；
先用一条验证，排查面是一条。这一步的成本远低于它避免的返工。

**估量**：S 　**依赖**：阶段 0 　**可与阶段 1 并行**

# 阶段 3 · 架构：能力表入库

> **为什么在功能之前**：`product_scope` 与 `domain`/`feature` 都**存在数据库里**，
> 而能力表是代码里的。不先纠正这个偏离，后面两个过滤无处安放。

| ID | 任务 | 验收 |
|---|---|---|
| **3.1** | 现有 162 行导出为**种子数据** | 导出结果可读、可 diff |
| **3.2** | `capability_table()` 改为读库 + 进程内缓存 | 启动时可加载 |
| **3.3** | **双轨过渡**：库优先，手写表兜底 | 库为空时行为与今天一致 |
| **3.4** | 灌入阶段 1 的抽取结果（约 1,400 行） | 行数 162 → 约 1,400 |
| **3.5** | 离线测试**不依赖数据库**（保留手写夹具） | 现有 387 测试仍全过 |
| **3.6** | 启动路径加"能力表加载失败"的显式错误 | 不静默降级到空表 |

**注意**：**3.5 不是可选项**——现有测试全部离线运行，若能力表变成必须读库，
测试套件就废了。必须保留一条不依赖数据库的路径。

**估量**：M 　**依赖**：阶段 0、2 　**风险**：🔴 高

| 时间 | 轨道 A（数据） | 轨道 B（代码） |
|---|---|---|
| 第 1 步 | — | **阶段 0 地基**（阻塞全部，必须最先） |
| 第 2 步 | **阶段 1 抽取管线** | **阶段 2 风险前置** |

| 第 4 步 | **阶段 6 实机验证**（可先起） | **阶段 4 产品过滤** ／ **阶段 5 归宿过滤** |

## 三条不可违反的顺序约束

1. **阶段 0 必须最先。** 两张表都是空的——这是改 schema 唯一的零成本窗口。
2. **阶段 2 必须在阶段 3 之前。** 高风险改动前先用一条能力证明行为一致。
3. **阶段 3 必须在阶段 4/5 之前。** 分类字段在数据库里，能力表在代码里；不先纠正这个偏离，过滤无处安放。

## 两条不可省略的护栏

1. **阶段 3.5：离线测试不得依赖数据库。** 现有 387 个测试全部离线；若能力表变成必须读库，测试套件即废。
2. **阶段 3.3：双轨过渡。** 库优先、手写兜底，跑通后再删。这是唯一能安全替换核心路径的方式。

## 立即可做的第一件事

**阶段 0.1 + 0.2**：定 schema 与取值表。

它**不依赖任何未定决策**（取值来自手册已有的 27 章与三个产品），**成本最低**，
且**解锁后面全部**。而它的窗口正在关闭——一旦灌了数据，成本就从"改一行 DDL"变成"写一次迁移"。
