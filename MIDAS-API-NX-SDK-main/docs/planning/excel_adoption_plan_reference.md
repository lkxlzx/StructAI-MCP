# `midas-nx` 초보자·일반 사용자 접근성 개선 플랜 (보류 — Excel 기능 설계 참고용)

> **상태 (2026-08-04)**: 우선순위는 `midas-nx-beginner-onboarding-structure-plan.md`(문서/온보딩 구조 개편)로 이동함.
> 이 문서는 활성 실행 계획이 아니라, 나중에 Excel round-trip(export/validate/preview/전송) 기능을
> 실제로 구현할 때 참고할 기술 설계 초안으로 보관한다 — 특히 검증 규칙(§ Journey 3),
> 의존 순서(Unit→Material→Section→Node→Element→Load, § Phase 6), 부분 실패 정책과 RunLog 필드
> 설계는 onboarding 계획의 P2 Excel 항목에 placeholder만 있고 여기에만 구체화돼 있다.

아래 계획을 기준으로 `midas-nx`를 Python 개발자뿐 아니라 Python 초보 구조 엔지니어와 Excel 중심의 일반 사용자도 안전하게 활용할 수 있는 도구로 발전시켜줘.

- 저장소: `Dennis5882/MIDAS-API-NX-SDK`
- PyPI 패키지: `midas-nx`
- 대상 제품: MIDAS Gen NX, MIDAS Civil NX
- 주요 운영체제: Windows
- 주요 사용자 도구: Microsoft Excel

## 프로젝트 배경

`midas-nx`는 마이다스아이티 재직자가 MIDAS NX Open API 문서와 실제 제품 검증을 바탕으로 개인적으로 개발·관리하는 직원 주도형 오픈소스 SDK다. 마이다스아이티 개발 조직이 공식적으로 출시하거나 유지보수하는 제품이 아니며, 회사의 공식 기술지원 대상도 아니다.

이 지위를 사용자에게 투명하게 설명하되, 프로젝트의 실제 제품 경험과 실환경 검증이라는 장점도 숨기지 마라.

## 이번 작업의 목적

현재 SDK는 개발자와 Python 초보자에게 의미 있는 기반을 제공하지만, 개발 경험이 전혀 없는 사용자는 설치, 인증, 코드 실행, 오류 해결과 Excel 연동에서 어려움을 겪을 수 있다.

이번 계획의 목적은 SDK의 엔드포인트 수를 더 늘리는 것이 아니다. 다음 사용자 경험을 만드는 것이 목적이다.

```text
Excel 템플릿 열기
→ 데이터 입력
→ 입력 검사
→ MIDAS 연결 확인
→ 변경 예정 내용 미리보기
→ 사용자 확인
→ MIDAS로 전송
→ 결과와 오류를 Excel에서 확인
```

사용자가 Python, HTTP, JSON, REST API를 이해하지 않아도 대표 업무를 완료할 수 있어야 한다.

# 1. 대상 사용자 정의

기능을 만들기 전에 다음 사용자 유형을 기준으로 요구사항을 분리해라.

## Persona A — Python 초보 구조 엔지니어

- Excel 사용에는 익숙하다.
- Python 코드를 읽거나 예제를 조금 수정할 수 있다.
- `pip`, 가상환경, 터미널에는 익숙하지 않다.
- 오류 메시지만 보고 문제를 해결하기 어렵다.
- 반복적인 모델 입력과 결과 정리를 자동화하고 싶다.

필요한 것:

- 단계별 설치 안내
- 복사해서 실행할 수 있는 예제
- 친절한 오류 메시지
- 안전한 기본값
- 업무 중심의 함수와 설명

## Persona B — Excel 중심 일반 사용자

- Python 코드를 작성하거나 수정하기 어렵다.
- Excel 표와 버튼만 사용하기를 원한다.
- MIDAS 모델 변경 전에 무엇이 바뀌는지 확인하고 싶다.
- 오류가 발생하면 Excel에서 원인과 해결 방법을 보고 싶다.

필요한 것:

- 표준 Excel 템플릿
- 실행 버튼 또는 별도 실행 프로그램
- 입력값 검증
- 변경 미리보기
- 행 단위 성공·실패 표시

## Persona C — 팀의 자동화 담당자

- Python을 어느 정도 사용할 수 있다.
- 여러 사용자의 설치와 버전을 관리해야 한다.
- 템플릿을 사내 업무에 맞게 확장하고 싶다.
- 로그, 배포, 업데이트 및 재현 가능한 환경이 필요하다.

필요한 것:

- 설정 파일
- 명확한 확장 지점
- 배포 패키지
- 진단 명령
- 호환성 및 업데이트 정책

# 2. 제품 원칙

모든 구현은 다음 원칙을 따라야 한다.

## 2.1 안전 우선

- 기본 시작점은 읽기 전용이어야 한다.
- 생성·수정·삭제는 명시적으로 구분한다.
- 전체 삭제나 새 프로젝트 생성은 일반 작업 버튼과 분리한다.
- 변경 전에 반드시 미리보기를 제공한다.
- 실패한 요청을 성공으로 표시하지 않는다.
- 네트워크 timeout이 실제 작업 실패를 의미하지 않을 수 있음을 안내한다.
- 중요한 모델에서는 사본과 저장을 권장한다.

## 2.2 점진적 공개

초보자에게 처음부터 모든 엔드포인트와 옵션을 보여주지 마라.

```text
기본 모드
→ 자주 사용하는 안전한 기능

고급 모드
→ 원본 JSON, 세부 옵션, 위험 작업
```

## 2.3 업무 용어 사용

다음과 같은 개발 용어를 사용자 화면의 중심에 두지 마라.

- HTTP 404
- JSON decode
- endpoint
- request body
- exception class

대신 다음처럼 표현한다.

- MIDAS NX 연결이 확인되지 않았습니다.
- MAPI-Key가 유효하지 않습니다.
- 17번째 행의 단면 번호가 모델에 없습니다.
- 분석 요청은 전달됐지만 완료 여부를 확인할 수 없습니다.

필요하면 기술 세부 정보는 “자세히 보기”에 제공한다.

## 2.4 재현 가능성

- 같은 입력으로 같은 요청을 생성할 수 있어야 한다.
- 실행한 패키지 버전과 NX 제품 정보를 기록한다.
- 입력, 검증 결과와 실행 결과를 추적할 수 있어야 한다.
- 비밀 정보는 로그와 Excel에 기록하지 않는다.

# 3. 우선 개발할 대표 사용자 여정

모든 기능을 동시에 만들지 말고 다음 순서로 완성해라.

## Journey 1 — 설치 및 연결 확인

사용자가 다음 질문에 답을 얻을 수 있어야 한다.

- Python이 설치되어 있는가?
- 지원되는 Python 버전인가?
- `midas-nx`가 설치되어 있는가?
- MIDAS Gen NX 또는 Civil NX가 실행 중인가?
- Open API 연결이 활성화되어 있는가?
- MAPI-Key가 유효한가?
- 현재 연결된 제품은 무엇인가?

결과 예:

```text
[성공] Python 3.12
[성공] midas-nx 0.14.0
[성공] MIDAS Gen NX 연결
[성공] MAPI-Key 확인
[안내] 중요한 모델을 수정하기 전에 파일을 저장하세요.
```

## Journey 2 — 현재 모델을 Excel로 가져오기

첫 번째 완성형 업무 흐름은 반드시 읽기 전용으로 만든다.

최소 대상:

- Project Information
- Unit
- Node
- Element
- Material
- Section

사용자는 버튼 또는 명령 하나로 현재 모델의 데이터를 Excel 파일에 내보낼 수 있어야 한다.

## Journey 3 — Excel 입력 검사

MIDAS로 전송하지 않고 Excel 데이터만 검증한다.

최소 검증:

- 필수 열 존재
- 빈 필수값
- 중복 ID
- 숫자 형식
- 참조하는 재료·단면·절점 ID 존재
- 요소의 절점 개수
- 제품별 미지원 기능
- 알려진 enum 값
- 위험한 문자열 길이

오류는 행·열·필드 기준으로 표시한다.

```text
시트: Elements
행: 12
열: NODE_J
문제: 절점 305가 Nodes 시트에 없습니다.
해결: Nodes 시트에 절점 305를 추가하거나 요소의 절점 번호를 수정하세요.
```

## Journey 4 — Excel에서 새 데이터 추가

읽기 전용 흐름과 검증 기능이 안정화된 후 다음 순서로 추가한다.

1. Material
2. Section
3. Node
4. Element
5. Static Load Case
6. Nodal Load 또는 Beam Load

초기 버전에서는 기존 항목 수정과 삭제를 제외하고 “새 항목 추가”만 지원하는 방안을 우선 검토한다.

## Journey 5 — 분석 및 결과 회수

쓰기 흐름이 안정화된 후 구현한다.

- 분석 실행 전 조건 확인
- 사용자 확인
- 충분한 timeout 안내
- timeout 이후 상태 불확실성 표시
- 분석 완료 여부 확인
- 기본 결과를 Excel로 회수

초기 결과 후보:

- Node displacement
- Reaction
- Beam force

# 4. 단계별 실행 계획

## Phase 0 — 현재 저장소 조사

코드를 변경하기 전에 다음을 조사하고 보고해라.

- 이미 존재하는 Quick Start와 예제
- 현재 CLI 또는 진단 기능 유무
- Excel 관련 코드 유무
- 환경변수와 MAPI-Key 처리
- 공통 오류 메시지와 hint
- 읽기 전용 endpoint 목록
- 위험 작업과 관련된 Known Issues
- 기존 선택적 의존성 구조

이미 충족된 요구사항은 중복 구현하지 마라.

산출물:

- 현재 상태 요약
- 재사용할 코드 목록
- 부족한 부분
- P0/P1/P2 구현 계획
- 공개 API 변경 가능성

## Phase 1 — Beginner Quick Start 개선

목표: Python 초보 사용자가 30분 이내에 연결 확인과 첫 읽기 요청을 완료한다.

구현 항목:

- Windows 중심 설치 안내
- Python 설치 확인 방법
- 가상환경을 몰라도 따라 할 수 있는 기본 절차
- MAPI-Key를 코드나 Excel에 직접 저장하지 않는 안내
- Gen/Civil 선택 방법
- 연결 확인 예제
- 현재 절점 읽기 예제
- 결과를 CSV 또는 XLSX로 저장하는 예제
- 자주 발생하는 오류와 해결 방법

Quick Start는 다음 세 단계로 구분한다.

1. 설치
2. 연결 확인
3. 첫 데이터 가져오기

각 단계에는 예상 정상 출력과 대표 오류 화면을 포함한다.

완료 기준:

- 새 Windows 환경을 기준으로 누락된 단계가 없다.
- 모든 명령을 복사해 실행할 수 있다.
- 실제 비밀 값이 문서에 없다.
- 기술 용어에는 짧은 설명이 있다.

## Phase 2 — 진단 도구

목표: 사용자가 코드를 작성하지 않고 환경과 연결 문제를 진단한다.

다음 형태를 검토한다.

```bash
midas-nx doctor
```

또는 패키지 구조상 CLI 추가가 적절하지 않다면:

```bash
python -m midas_nx.doctor
```

필수 검사:

- Python 버전
- SDK 버전
- 운영체제
- 기본 URL
- 선택 제품
- MAPI-Key 존재 여부
- MAPI-Key 값은 절대 출력하지 않음
- 네트워크 연결
- `verify_connection()` 결과
- 제품 불일치
- 알려진 방화벽·SSL inspection 가능성

출력 모드:

- 사람이 읽는 기본 출력
- 지원 요청용 JSON 출력

지원 요청용 출력에서도 MAPI-Key, 이메일, connection ID와 민감한 경로를 마스킹한다.

완료 기준:

- 정상·인증 실패·제품 미연결·timeout·비 JSON 응답 테스트가 있다.
- 모든 오류에 다음 행동이 안내된다.
- 진단 명령은 모델 데이터를 변경하지 않는다.

## Phase 3 — 업무별 Recipe

목표: 사용자가 API 매뉴얼을 읽지 않고 대표 업무를 수행한다.

최소 Recipe:

1. 현재 모델 정보 확인
2. Node를 Excel로 내보내기
3. Material과 Section 읽기
4. Excel에서 Node 추가
5. Excel에서 Element 추가
6. 정적 하중 입력
7. 분석 실행
8. 반력과 변위 결과 저장
9. 오류 로그 저장

각 Recipe에는 다음을 포함한다.

- 무엇을 하는 예제인지
- 실행 전 조건
- 위험 수준: 읽기 전용 / 변경 / 고위험
- 준비할 Excel 열
- 전체 실행 코드
- 예상 결과
- 흔한 오류
- 원상복구 또는 후속 확인 방법

Recipe는 서로 독립적으로 복사·실행할 수 있어야 한다.

## Phase 4 — Excel 읽기 전용 MVP

목표: Python 코드를 수정하지 않고 현재 MIDAS 모델을 Excel로 내보낸다.

권장 구성:

```text
excel_tool/
├─ README.md
├─ templates/
│  └─ midas_nx_model_export.xlsx
├─ export_model.py
├─ config.example.toml
└─ tests/
```

저장소 구조에 더 적합한 위치가 있으면 이유를 설명하고 조정한다.

Excel 출력 시트:

- `README`
- `Connection`
- `Project`
- `Units`
- `Nodes`
- `Elements`
- `Materials`
- `Sections`
- `RunLog`

요구사항:

- 기존 파일을 조용히 덮어쓰지 않는다.
- 기본 출력 파일명에 날짜와 시간을 포함한다.
- 각 시트에 단위와 필드 설명을 제공한다.
- 연결과 SDK/NX 버전 정보를 기록한다.
- MAPI-Key를 기록하지 않는다.
- 부분 실패 시 성공한 시트와 실패한 시트를 구분한다.
- 전체 실패가 아니면 생성된 파일을 보존하고 경고를 표시한다.

라이브 MIDAS NX 없이 mock 데이터를 사용한 Excel 생성 테스트를 제공한다.

## Phase 5 — Excel 입력·검증 MVP

목표: Excel 입력값을 MIDAS에 보내기 전에 안전하게 검증하고 변경 계획을 만든다.

템플릿 시트:

- `Instructions`
- `Settings`
- `Materials`
- `Sections`
- `Nodes`
- `Elements`
- `Validation`
- `Preview`
- `RunLog`

상태 열 예:

- `ACTION`: ADD / SKIP
- `VALIDATION_STATUS`
- `MESSAGE`

첫 버전의 제한:

- ADD와 SKIP만 허용
- UPDATE와 DELETE는 비활성화
- 사용자가 작성하지 않은 수식 셀을 데이터로 보내지 않음
- 빈 행은 무시
- Excel 표시값과 실제 내부값 차이를 주의

검증 후 `Preview` 시트에 다음을 생성한다.

```text
추가 예정 Material: 2
추가 예정 Section: 4
추가 예정 Node: 120
추가 예정 Element: 98
오류: 3
경고: 7
```

검증 오류가 하나라도 있으면 기본적으로 전송을 막는다. 경고만 있는 경우 사용자 확인 후 진행할 수 있다.

## Phase 6 — Excel에서 MIDAS로 안전하게 전송

목표: 검증된 ADD 작업을 사용자 확인 후 전송한다.

전송 순서:

1. 연결 확인
2. 제품 확인
3. 입력 파일 fingerprint 계산
4. 검증 재실행
5. 변경 요약 표시
6. 사용자 확인
7. 의존 순서대로 전송
8. 행 단위 결과 기록
9. 후속 GET으로 가능한 범위에서 반영 확인
10. 실행 로그 저장

의존 순서 예:

```text
Unit
→ Material
→ Section
→ Node
→ Element
→ Load Case
→ Load
```

부분 실패 정책을 명확하게 설계해라.

- 어디까지 성공했는지 기록
- 실패 이후 계속 진행해도 안전한지 판단
- 무조건 자동 rollback을 약속하지 않음
- API가 transaction을 지원하지 않으면 그 사실을 분명히 표시
- 재실행 시 중복 생성 가능성을 검사

## Phase 7 — Excel 버튼 또는 실행 프로그램

- xlwings Add-in

- 설치 난이도
- 회사 PC의 보안 정책
- 관리자 권한 필요 여부
- Excel 버전 호환성
- 업데이트 편의성
- 백신 오탐 가능성
- 디버깅과 지원 난이도

2. 안정화 후 Excel 버튼

## Phase 8 — 일반 사용자용 오류 경험

공통 오류를 다음 구조로 표현한다.

```text
무슨 문제가 발생했는가
→ 작업이 반영되었을 가능성이 있는가
→ 사용자가 지금 무엇을 해야 하는가
→ 기술 세부 정보
```

예:

```text
분석 완료 여부를 확인할 수 없습니다.

서버가 제한 시간 안에 응답하지 않았지만 MIDAS NX에서는 분석이 계속되고
있을 수 있습니다. 같은 분석 요청을 즉시 다시 보내지 마세요.

1. MIDAS NX 화면에서 분석 상태를 확인하세요.
2. 분석이 끝났다면 결과 가져오기를 실행하세요.
3. MIDAS NX가 응답하지 않으면 작업 파일의 저장 상태를 확인하세요.

기술 정보: MidasConnectionError / read timeout / 30 seconds
```

오류 코드 체계가 필요하면 사용자용 코드와 내부 예외명을 분리한다.

## Phase 9 — 배포와 업데이트

목표: 일반 사용자가 Python 환경을 직접 관리하지 않아도 도구를 설치·업데이트할 수 있는 경로를 마련한다.

먼저 다음 두 배포 모델을 비교한다.

### 관리형 Python 환경

- 설치 스크립트가 가상환경 생성
- 고정된 SDK 버전 설치
- 실행 바로가기 생성
- 문제 발생 시 환경 재생성 가능

### 단일 실행 파일

- Python 설치 불필요
- 배포가 간단해 보임
- 파일 크기와 백신 오탐 가능성
- 디버깅과 패키지 업데이트가 어려울 수 있음

초기에는 관리형 Python 환경을 우선 고려한다. 단일 실행 파일은 실제 사용자 환경 검증 후 결정한다.

업데이트 시:

- 자동으로 기존 설정과 템플릿을 삭제하지 않는다.
- SDK와 Excel 템플릿 버전 호환성을 확인한다.
- breaking change가 있으면 실행 전에 중단하고 안내한다.
- 이전 버전으로 돌아가는 방법을 문서화한다.

# 5. Excel 템플릿 설계 지침

## 5.1 색상과 상태

색상만으로 의미를 전달하지 말고 텍스트 상태를 함께 사용한다.

- 입력 가능
- 자동 계산
- 읽기 전용
- 경고
- 오류

## 5.2 필드 설명

열 제목에는 짧은 업무 용어를 사용하고, API 원본 필드명은 별도 행이나 설명에 표시한다.

예:

| 사용자 표시 | API 필드 |
|---|---|
| 절점 번호 | ID |
| X 좌표 | X |
| 재료 번호 | MATL |
| 단면 번호 | SECT |

## 5.3 단위

- 현재 단위계를 파일 상단에 표시한다.
- 숫자 열의 단위를 열 제목 또는 설명에 표시한다.
- 단위가 불명확하면 전송을 막거나 강한 경고를 표시한다.
- 자동 단위 변환은 별도의 명시적 기능으로만 제공한다.

## 5.4 수식과 값

- Excel 수식 셀의 계산 결과를 읽을 때 주의한다.
- 수식이 재계산되지 않은 파일을 감지할 수 있는지 검토한다.
- 숫자로 보이는 문자열, 공백, 천 단위 구분 기호를 명확하게 처리한다.
- 날짜와 자동 서식이 ID를 바꾸지 않도록 한다.

## 5.5 로그

`RunLog`에는 다음을 기록한다.

- 실행 시간
- 도구 버전
- SDK 버전
- 제품
- 작업 종류
- 입력 파일 fingerprint
- 성공·실패·경고 개수
- 행별 결과
- 민감정보가 제거된 오류 정보

MAPI-Key, 사용자 이메일, connection ID는 기록하지 않는다.
